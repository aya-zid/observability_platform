# Medianet Observability Platform

A full-stack SaaS observability platform for monitoring servers, containers, and services. Similar to Datadog — customers sign up, install a lightweight agent on their servers, and get real-time dashboards, centralized logs, smart alerts, AI-powered reports, and CVE vulnerability scanning.


---

## What It Does

- **Agent-based discovery** — install one command on a server, it auto-detects running services (Nginx, Apache, PostgreSQL, MariaDB, Redis, PHP-FPM, Docker containers)
- **Real-time dashboards** — CPU, memory, disk, network, plus per-service metrics (request rates, response times, connections, cache hit ratios)
- **Centralized log aggregation** — collect and search logs from all services in one place
- **Smart alerting** — 60+ pre-built alert templates with cross-tier incident correlation
- **AI-powered reports** — daily infrastructure summaries generated by Google Gemini / Groq
- **CVE vulnerability scanning** — automatic NVD correlation against discovered service versions
- **Multi-tenant SaaS** — subscription plans, billing, team management, role-based access control

## Quick Start

### Prerequisites

- Docker and Docker Compose
- Git

### 1. Clone the repository

```bash
git clone https://gitlab.medianet.tn/pfe/2026-aya-zid/medianet_observability.git
cd observability-platform
```

### 2. Create the shared Docker network

```bash
docker network create obs-network
```

### 3. Start the observability stack (metrics/logs storage)

```bash
cd infrastructure
docker compose up -d
cd ..
```

### 4. Start the platform

```bash
cd platform
docker compose up -d --build
```

### 5. Open the applications

| Application | URL | Purpose |
|---|---|---|
| Customer Frontend | http://localhost:5173 | Sign up, install agent, view dashboards |
| Admin Panel | http://localhost:5174 | Manage tenants, subscriptions, packs |
| pgAdmin (dev only) | http://localhost:5050 | Browse the database |
| Backend API | http://localhost:8080 | REST API |

### 6. First-time setup

1. Go to **http://localhost:5174** (admin panel) and sign up as a platform admin
2. Create subscription packs (pricing tiers) in the admin panel
3. Go to **http://localhost:5173** (customer frontend) and sign up as a customer
4. Go to **Settings** and copy the agent install command
5. Run the install command on a server with services to monitor

## How It Works

```
Customer's Server                    Platform
+-----------------+                 +------------------+
| Agent (otelcol) | --- metrics --> | VictoriaMetrics  |
|                 | --- logs -----> | Loki             |
|                 | --- heartbeat -> | Go Backend       |
| Auto-detects:   |                 |   - Auth         |
|   nginx         |                 |   - Discovery    |
|   postgres      |                 |   - Alert Engine |
|   redis         |                 |   - AI Reports   |
|   mariadb       |                 |   - CVE Scanner  |
|   phpfpm        |                 |   - Billing      |
|   containers    |                 +------------------+
+-----------------+                        |
                                            v
                                     +------------------+
                                     | React Frontend   |
                                     |   Dashboards     |
                                     |   Logs           |
                                     |   Alerts         |
                                     |   Reports        |
                                     +------------------+
```

1. **Agent** is installed on customer servers via a one-line curl command
2. Agent **auto-discovers** running services and registers them with the platform
3. Agent collects **metrics** (Prometheus remote_write), **logs** (OTLP), and sends **heartbeats**
4. Backend **stores data** in VictoriaMetrics (metrics) and Loki (logs), with per-tenant isolation
5. **Alert engine** continuously evaluates rules against live data, fires notifications
6. **CVE scanner** checks service versions against NVD every 2 hours
7. **AI reports** generate daily infrastructure summaries using Gemini/Groq
8. **Frontend** displays dashboards, logs, alerts, and reports in real-time

## Supported Services

The agent can auto-detect and monitor these services:

| Service | Metrics | Logs | Dashboards |
|---|---|---|---|
| **Nginx** | stub_status (built-in) | access.log, error.log | Request rates, response times, status codes, slow requests, IP investigation |
| **Apache** | mod_status (built-in) | access.log, error.log | Same as Nginx |
| **PostgreSQL** | postgres_exporter | postgresql.log | Connections, queries/sec, cache hit, replication lag, database health |
| **MariaDB** | mysqld_exporter | mysql.log, error.log | Connections, queries/sec, slow queries, InnoDB stats, query digests |
| **Redis** | redis_exporter | syslog/journald | Connected clients, memory, hit rate, ops/sec |
| **PHP-FPM** | php-fpm_exporter | php-fpm.log | Active/idle processes, request duration, queue depth |
| **Docker** | cAdvisor metrics | container logs | CPU, memory, network, disk I/O per container |
| **Linux Hosts** | node_exporter | syslog/journald | CPU, memory, disk, network, processes |

## Backend Background Workers

The Go backend runs 6 background workers that continuously process data:

| Worker | Interval | Purpose |
|---|---|---|
| Alert Engine | Every 30s | Evaluates alert rules against live PromQL/LogQL queries, creates/resolves events |
| Notification Dispatcher | Event-driven | Sends HTML alert emails via SMTP |
| Usage Metering | Every 5 min | Flushes Redis usage counters to PostgreSQL daily rows |
| Subscription Expiration | Every 1 hour | Marks expired subscriptions and trials |
| Retention Cleanup | Every 1 min | Enforces per-plan log/metric retention in Loki and VictoriaMetrics |
| CVE Scanner | Every 2 hours | Scans NVD for CVEs matching discovered service versions |

See [platform/README.md](platform/README.md) for detailed explanations of how each worker works.

## Production Deployment

### What to Change Before Going Live

1. **Credentials** — change `JWT_SECRET`, `REFRESH_TOKEN_PEPPER`, `DB_PASSWORD` in `platform/backend/.env`
2. **API keys** — set real Gemini/Groq/NVD keys
3. **SMTP** — configure a real email provider
4. **CORS** — set `CORS_ALLOW_ORIGINS` to your production domain
5. **Cookies** — set `COOKIE_SECURE=true` and `COOKIE_DOMAIN`
6. **pgAdmin** — remove from `docker-compose.yml`
7. **Database** — use managed PostgreSQL (RDS, Cloud SQL)
8. **Redis** — use managed Redis (ElastiCache, Cloud Redis) with a password
9. **TLS** — run behind a reverse proxy (nginx, traefik, Caddy)

### Recommended Architecture

```
Internet
    |
    v
[nginx/traefik]  -- TLS termination
    |
    +--> [Frontend]     -- static files
    +--> [Admin]        -- static files + API proxy
    +--> [Backend]      -- Go API
              |
              +--> [PostgreSQL]  -- managed
              +--> [Redis]       -- managed
              +--> [VictoriaMetrics]
              +--> [Loki]
```
